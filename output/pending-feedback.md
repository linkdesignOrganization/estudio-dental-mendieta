### Feedback de: visual-checker
**Contexto:** validación post-deployment 6b — verificación de optimización de fotos (67MB→1.72MB) + topología 1 dominio en producción.

- **Verificación de bytes optimizados (anti-caché de las gordas):** medir `transferSize` vía Resource Timing API en producción NO es fiable cuando el browser ya cacheó los assets (devuelve ~300B/encodedBodySize=0 = cache hit). El método autoritativo es descargar la foto directamente (curl / Playwright `request.get` → `body().length` + `content-type`) y parsear las dimensiones del JPEG (SOF marker) — eso da peso real y `naturalWidth` independientemente del estado de caché. Patrón reutilizable para futuras verificaciones de optimización de imágenes.
- **`getEntriesByType('largest-contentful-paint')` no es válido** en el Chromium del MCP (LCP solo vía PerformanceObserver) y emite una warning de consola que puede confundirse con un error del app — usar `domContentLoaded`/`loadEvent`/`domInteractive` del navigation entry para timing observacional, o un PerformanceObserver real para LCP.
- **REQ-272 (cero tracking/demo) se verifica mejor en capas:** (1) intercept de red por blocklist de hosts, (2) Resource Timing para hosts contactados, (3) **escaneo del bundle JS descargado** (firmas de SDK como `gtag(`/`dataLayer`/`fbq(`, flags `isDemo`/`demoMode`, URLs externas), (4) scan de texto visible + HTML source. La capa (3) es la más fuerte: con CSP `script-src 'self'` cualquier tracking tendría que estar embebido, así que escanear los chunks lo cierra definitivamente.
- **Bash en este sandbox pierde el PATH dentro de loops `while/for` con subshells** (curl/awk/tr → "command not found"). Para iterar sobre N requests HTTP con parsing, usar un script Python (`/usr/bin/python3`) de una sola invocación en vez de un loop de shell — más robusto y evita falsos negativos masivos.
- **Variable `status` es read-only en zsh** — no usarla como nombre de variable en scripts bash/zsh; usar `st`/`http_status`.
- **Avatares con `app-avatar` (px fijos + object-fit:cover):** el conteo de `<img>` puede duplicarse porque coexisten en el DOM la vista tabla y la vista cards (una oculta por CSS); las `<img>` "pending" de la vista oculta tienen `currentSrc` válido y `loading=lazy`, NO son rotas. Filtrar broken estrictamente por `complete && naturalWidth===0 && tieneSrc` para no marcar las diferidas/ocultas como bug.

### Feedback de: flow-tester
**Contexto:** validación post-deployment 6b — GIFs de EVIDENCIA del recorrido E2E del sistema final en producción (Azure SWA), para el cierre/entrega.

- **GIFs reproducibles sin video→gif:** el patrón más robusto y de mejor calidad es capturar frames con `page.screenshot({animations:'disabled', caret:'hide'})` en un timer (cadencia fija ~350ms) + marcas explícitas en los beats clave, y ensamblar con `ffmpeg` paleta lanczos (palettegen `stats_mode=diff` + paletteuse `dither=bayer`). La conversión del video de Playwright a GIF es frágil y pesada; el screenshot-timer da control total sobre los frames y peso acotado (~350–520 KB por GIF de recorrido). Scripts dejados como `e2e/_record-gifs.mjs` / `e2e/_record-gif-mobile.mjs`.
- **Lista de pacientes = DOS árboles DOM sincronizados (tabla `<tr>` + cards `.dt__card`) con el MISMO `aria-label="Ver ficha de …"`:** en mobile el `<tr>` está OCULTO y `.dt__card` visible, así que `[aria-label^="Ver ficha de"].first()` cae en el `<tr>` oculto → timeout ("resolved to hidden"). SIEMPRE filtrar `.filter({ visible: true })` (mismo contrato que `patientRow()` en `_helpers/seed.ts`). Esto ya está documentado en el helper — conviene usar el helper en vez de re-escribir el selector en scripts ad-hoc.
- **Selectores estables ya verificados del sistema (reutilizables para evidencia/E2E):** login = `link` "Ingresar como administradora" (es `<a>`, NO `<button>`) → navega a `/reportes`; odontograma pieza editable = `radiogroup` "Estado de la pieza" (6 radios) + botón "Guardar estado"; crear turno 3 pasos = `/agenda/nuevo/paciente` → `/agenda/nuevo/profesional` (`getByLabel('Profesional')` + `textbox` "Fecha" + slot `button` "HH:MM") → `/agenda/nuevo/confirmar` → "Confirmar turno"; pago = `#pay-amount/#pay-date/#pay-method/#pay-note` + "Confirmar pago" + toast "Pago registrado." + saldo en `.pay__stat` "Saldo pendiente"; reportes detallados = `main figure` (5/5/3/4 figuras por reporte).
- **Acceso público sin auth (topología 1 dominio):** confirmado con un sweep de deep-links directos (cada `goto` arranca desde la URL profunda) verificando status 200 + que `landed` NO contiene `/login`. El guard `seedReadyGuard` hidrata el store y NO redirige. Patrón rápido y contundente para la verificación de topología de un SPA sin backend.
- **Módulos que mutan estado en producción (odontograma, crear turno, registrar pago):** grabar SIEMPRE sobre seed fresco (`resetSeed` antes) y revertir al terminar (`resetSeed` final = `localStorage.removeItem('edm:v1:state')` + reload → el `SeedReadyGuard` re-hidrata el seed byte-idéntico). Deja producción intacta para el siguiente visitante; imprescindible cuando el "entorno de prueba" ES el sitio entregado al cliente.
- **Módulos ESM ad-hoc fuera del proyecto fallan a resolver `@playwright/test`:** un script en `/tmp` da `ERR_MODULE_NOT_FOUND` porque `node_modules` vive bajo el proyecto. Colocar el script dentro del directorio del proyecto (junto a `node_modules`) para que resuelva; ejecutar con `cd <proyecto> && node script.mjs`.
